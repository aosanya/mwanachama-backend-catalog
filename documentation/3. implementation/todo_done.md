| CAT0 | The spec refuses at load what the database would merge silently | 2026-09-23 | Four gaps found reviewing `spec/` for the website's W16 naming decision, all closed in `spec.Validate`, plus the naming change itself. **The name:** `TableFor` is now `<instance>_<module>_<table>` — `agency_catalog_agencies` — where it was `<instance>_<table>`. The module segment is what lets two modules share one database without arranging not to collide: a catalog instance named `agency` and an agency instance of the same name both wanted `agency_agencies`, and neither module would have noticed, because GORM's `AutoMigrate` adopts a table that already exists and adds the missing columns (verified by running it: no error, and both modules' rows then live in one table) while this package's own `create table if not exists` is a no-op against one. **The four gaps:** (1) `Module` was checked for non-empty only — fine as a label, wrong once it is a segment of every table name. It and `Instance` are now held to a new `SegmentPattern` (`^[a-z][a-z0-9]*$`), stricter than `NamePattern` by exactly the underscore, because `<instance>_<module>_<table>` with underscores legal inside the first two segments cannot be read back apart. (2) No identifier budget existed; `MaxIdentifier = 63` now measures every name the spec emits. (3) Duplicate detection was on the *declared* table name, so two objects differing only past the cut passed validation and then shared one relation — it is now keyed on `TableFor`'s output. (4) Index names were unchecked although `<table>_<index>_idx` is always longer than the table it derives from, and Postgres keeps indexes in the same per-schema namespace as tables, so one map covers both kinds, via a new `Spec.IndexFor` that `migrate.go` calls instead of rebuilding the name. **Evidence rather than theory:** `…_catalog_entries` and `…_catalog_entry_privates` under a real 51-character published slug both truncate to `…_catalog_ent`, confirmed against the live `mwanachama-2` project, and 337 of the 634 published slugs are over the 31-character budget that an 11-character module and a 19-character object leave. Both new tests were mutation-checked — widening `MaxIdentifier` and restoring `NamePattern` on the segments each make them fail. Also tidied `Parse`'s `[]byte → string → strings.NewReader` round trip to `bytes.NewReader`. `gofmt`, `go build`, `go vet` and `go test ./...` all clean. Recorded on the website's board as W18. |
| CAT1 | Retired `gormstore/` — the objects are declared, and no longer written too | 2026-09-23 | Nine row structs with `ToRow`/`RowTo` pairs either side, plus `jsondoc.go`, `tables.go` and the root `tables.go` re-export, all deleted: the same nine objects were described twice, once as data in the spec and once as Go. **What replaces them** is `store.go` — roles, table lookup and a row codec — and `NewCatalogManager(db, *spec.Spec)`. Three choices worth keeping. (1) **A column is found by field name, not by json tag.** `columnName` turns `SubmittedBy` into `submitted_by` and `RunID` into `run_id`. The tag looked like the obvious join and is wrong exactly where it hurts: `ShareLink.KeyHash` is `json:"-"` so a hash never reaches an API response, and a tag-reading codec silently stops storing it. Mutation-checked — the tag-reading variant fails `TestEncode_CarriesAFieldThatJSONHides` and five real share-key tests with it. (2) **Every declared column is written every time.** A map missing a key means "leave it alone" to an update, so omitting empty values would make clearing a field impossible; mutation-checked against `approved_at`, which an Entry must lose when its document changes. (3) **The spec and the types are checked against each other in `NewCatalogManager`**, both directions, so a declared column with nowhere to land fails at construction rather than dropping a value on every write. Ids moved from GORM `BeforeCreate` hooks, which a map-shaped write never reaches, to `newID()` at the call sites. `cmd/import` takes `-spec` in place of `-instance`. **Acceptance met:** every behaviour CLAUDE.md lists keeps its test and still passes, and `routes/routes_test.go`'s bodies are untouched — only its setup changed, from `DefaultTableNames("test")` to loading the shipped `spec/examples/agency.catalog.json`, which now also means the suite runs against the declaration this module actually ships. While in here: `spec/spec.go` was 455 lines against this repo's 300-line rule, so validation moved to `spec/validate.go`; no file is now over 300. `gofmt`, `go build`, `go vet`, `go test ./...` all clean. |
| CAT3 | Shrank `models/` — the declarable rules moved into the spec | 2026-09-23 | `models/` held a second copy of what the spec already declares: six closed-vocabulary maps with their `IsX` functions, and four `Validate` methods re-checking `required`, slug shape and enum membership field by field. `validate.go` now reads `required`, an enum's `values` and `matches` off the object and applies them on the way in, so **the permitted states are the domain's to declare** — `TestVocabularyComesFromTheSpec` shows both directions: the shipped spec refuses a fourth visibility, and a spec declaring one accepts it with no Go change. Mutation-checked by editing the JSON alone: dropping `matches: "slug"` breaks the two bad-slug cases, dropping `required` on `name` breaks the no-name case. `matches` names a pattern and this module supplies the meaning (`slug`, `json_object`); a spec naming one nobody supplies is an error, not a rule that quietly never runs. **What stays in Go is what a spec cannot say**, each beside the type it is about: `PageView.SlugFitsPage` (one field's presence depending on another's value) and the non-negative checks on `Rank`, `Attempts` and `TemplatesFiled`. `Check(spec, role, value)` is the same validation without a database, which is what `cmd/import` uses to validate 623 folders before opening a connection. The existing refusal tests — seven Entry cases, three private, the page-view and suggestion ones — were written against the old `Validate()` methods and all still pass unchanged, which is the evidence that nothing got weaker. **Two duplications closed in passing:** `models.DocPathPattern` was a byte-identical copy of `spec.DocPathPattern` guarding the same injection surface (two things that can drift, and the one that drifts looser is the one nobody notices), and `entry.go` built its own document-path SQL although `spec.DocPathExpr` exists and is what the migrator builds the matching index with — an expression index applies only to a query whose expression matches it exactly, so a copy drifting by a space would have left every document filter doing a full scan silently. Both now go through the one function; the emitted SQL is unchanged in both dialects. `models/` is 534 → 446 lines. `gofmt`, `go build`, `go vet`, `go test ./...` clean. |
